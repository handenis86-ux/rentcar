# План реализации RentCar — для Музаффара и Искандара

Цель: довести проект до работающего MVP и первых заявок, параллельно научив Музаффара работать с Claude Code.

**Что уже есть:** Next.js 15 с i18n (`[locale]`), страницы-каркасы (cars, blog, about, contact, faq, login, register, terms, privacy), `prisma/schema.prisma`, дизайны в Pencil, репозиторий на GitHub.

**Чего нет:** реальной БД, данных, бронирования, платежей, админки, контента.

---

## Фаза 0 — Настройка окружения (1 день)

1. Установить Claude Code, войти под своей подпиской, открыть проект в VS Code.
2. Попросить Claude: *«покажи структуру проекта и объясни, что уже сделано»*.
3. Освоить 3 базовые вещи: `/clear` (очистка контекста), `/plan` (режим планирования), `Esc` (прерывание).
4. Подключить Vercel к репозиторию для автодеплоя с `master`.

**Правило для Музаффара:** Claude хорош, когда задача маленькая и конкретная. «Сделай сайт» — плохо. «Добавь на странице /cars фильтр по коробке передач» — хорошо.

---

## Фаза 1 — База данных (2–3 дня)

1. Открыть `prisma/schema.prisma`, попросить Claude дополнить модели: `Car`, `Booking`, `User`, `Review`, `Company` (арендодатель), `City`.
2. Поднять Postgres на Neon или Supabase (бесплатный тариф), прописать `DATABASE_URL` в `.env`.
3. Запустить `npx prisma migrate dev` — Claude подскажет команды.
4. Написать сид-скрипт с 20–30 демо-машинами (марки, цены, фото из `/public`).

**Чекпоинт:** в БД есть машины, Prisma Studio их показывает.

---

## Фаза 2 — Экспорт дизайна из Pencil (1–2 дня)

1. Дизайны лежат в `.pen` файлах — читать их ТОЛЬКО через MCP `pencil`, не обычным Read.
2. Попросить Claude: *«посмотри текущую страницу в Pencil и перепиши [locale]/cars/page.tsx под этот дизайн, используя Tailwind»*.
3. Идти **по одной странице:** главная → каталог → карточка машины → форма бронирования. Не всё сразу.
4. Переиспользуемые компоненты класть в `src/components/`.

**Правило:** после каждой страницы — git-коммит. Если что-то сломалось, `git checkout` откатит.

---

## Фаза 3 — Каталог и карточка машины (3–4 дня)

1. `/cars` — список из БД, фильтры (город, класс, цена, КПП, даты).
2. `/cars/[slug]` — карточка: галерея, цена, условия, кнопка «Забронировать».
3. Поиск с главной → редирект в `/cars?city=...&from=...&to=...`.
4. Мультиязычность (RU / UZ / EN) через `messages/` — Claude покажет, как добавлять ключи.

---

## Фаза 4 — Бронирование (MVP без платежей) (3 дня)

1. Форма брони → запись в БД со статусом `pending`.
2. Telegram-бот уведомлений: создать бота у @BotFather, токен в `.env`, при новой броне — сообщение админу. Claude напишет хендлер за 10 минут.
3. Email клиенту через Resend (бесплатный тариф).

**Это и есть MVP.** На этом этапе уже можно запускать сайт и обрабатывать заявки руками.

---

## Фаза 5 — Контент и SEO (параллельно, постоянно)

1. Блог: 10–15 статей через скилл `market-seo`. Темы: «аренда авто в Ташкенте», «ПДД Узбекистана для туристов», туристические маршруты.
2. `sitemap.xml`, `robots.txt`, meta-теги, Open Graph — попросить Claude настроить разом.
3. Google Search Console + Яндекс.Вебмастер.

---

## Фаза 6 — Платежи (когда пойдут первые заявки) (3–5 дней)

1. Click и Payme — у них есть документация на русском. Скормить её Claude: *«вот документация Click, сделай интеграцию для бронирования»*.
2. Тестовый режим → продакшн.

---

## Фаза 7 — Админка (5 дней)

1. `/admin` с простой авторизацией (NextAuth). Список броней, смена статусов, CRUD машин.
2. Можно взять готовую либу — попросить Claude сравнить варианты и выбрать.

---

## Правила работы с Claude (самое важное для новичков)

- **Одна задача — одна сессия.** Закончили фичу → `/clear` → новая.
- **Всегда смотреть diff** перед принятием. Claude иногда удаляет лишнее.
- **Git после каждого шага.** Это страховка. Искандар должен выучить `git add / commit / push`.
- **Не бояться говорить «нет»** и переделывать. Объясни, что не так — Claude исправит.
- **План перед кодом.** На сложных задачах писать: *«составь план, ничего не меняй»*, читать, соглашаться, потом *«выполняй»*.
- **Документация фреймворка лежит в `node_modules/next/dist/docs/`** (см. AGENTS.md). Next.js 15 отличается от того, что Claude «помнит» из обучения — всегда сверяться.

---

## Роль Музаффара

**Не кодить, а ставить задачи и проверять результат.** Открывать сайт в браузере после каждой фазы, кликать, ломать, возвращать Искандару список багов. Это и есть роль «продакта с Claude».

## Роль Искандара

Руки: переносит задачи от Музаффара в Claude, смотрит diff, коммитит, деплоит, разбирается с ошибками сборки.
